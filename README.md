# 获客助手 网页版

在自己的浏览器里采小红书的帖子和评论，挑出想找对象的人，生成能直接发的私信。Mac 和 iPhone 都能用，不用装 app，不用 Xcode，不用开发者账号。

安装和使用说明在 <https://goose666666.github.io/xhs-collect-web/>。

## 这是什么

一个用户脚本加一个静态网站。

用户脚本挂在小红书页面上，在页面右下角加一个面板。面板负责选词、跑采集、看数据、出话术。采到的东西存在浏览器的 IndexedDB 里，不上传任何地方。

静态网站做两件事：给出安装步骤，以及提供一个看板，把导出的 json 文件在电脑上打开来看。

## 为什么不是一个普通网页

托管在 GitHub Pages 上的网页登不了小红书也采不了数据。浏览器的同源策略挡着，页面既读不到小红书的 cookie，也钩不到它页面里的 fetch。

所以采集这部分必须跑在小红书自己的页面上，这正是用户脚本能做而普通网页做不到的事。登录也因此不需要单独做：用户在 Safari 里正常登录小红书，脚本用的就是那个会话。

## 原理

跟安卓版是同一套。安卓版在自己的 WebView 里注入脚本钩住 fetch 和 XHR，网页版把同一段脚本注入到小红书页面里，钩的是同一批接口，解析用的是同一套字段规则。

小红书的接口带签名，自己拼请求几乎不可能。但只要让页面自己去请求，返回就是完整的，跟人工浏览没有区别，我们只是把返回的 JSON 抄一份。

## 跟安卓版最大的不同

安卓版整轮采集跑在一个不会消失的对象里。网页版每打开一篇帖子就是一次真正的页面跳转，脚本会被整个重新加载，内存里的东西全没。

所以 `70-engine.js` 写成一台状态机：每走一步就把进度写回库，新页面起来之后读回进度，看自己该干什么，接着干。中途关掉标签页、手机锁屏、甚至重启浏览器，回到小红书都能接着跑。

## 目录

```
src/                脚本源码，按加载顺序编号
  10-util.js        取值和时间
  20-parse.js       接口 JSON 拆成笔记和评论
  30-store.js       IndexedDB
  40-industry.js    行业配置
  45-limits.js      采集节奏
  50-funnel.js      风控漏斗和意向分层
  55-reply.js       私信话术
  58-csv.js         导出
  60-hook.js        钩住页面的 fetch 和 XHR
  70-engine.js      采集状态机
  80-ui.js          悬浮面板
  90-main.js        入口
docs/               GitHub Pages 的根目录
  index.html        安装说明
  viewer.html       看板
  xhs-collect.user.js  构建产物
  assets/lib.js        构建产物，看板用
test/run.js         纯函数测试
build.js            拼接构建
```

## 构建和测试

```
node build.js
node test/run.js
```

构建只做拼接，不打包不压缩。这个脚本要装在别人的浏览器里，跑在他自己的账号上，看不懂的代码不该让人装。

测试里的断言是从安卓版 `test/` 下的 Dart 测试搬过来的，值一模一样。两端的解析和话术必须给出同样的结果，不然手机采的和网页采的数据摞不到一起。

## 跟另外两端的关系

三端的表结构和字段名完全一致：

- 电脑版 Python 加 Playwright，在 `手机软件/小红书获客智能体`
- 安卓版 Flutter，在 `D:\software\xhs-app`
- 网页版就是这个仓库

导出的 json 和 csv 可以在三端之间互相导入。

## 限速是硬约束

默认三十分钟采五十篇。小红书识别批量行为看的是节奏，不是浏览器指纹。密集访问轻则接口返回空数据、弹滑动验证，重则封号。慢一点最多是多花几小时，号没了是全部归零。

私信一律手工发，面板只把话复制到剪贴板。自动群发是账号被封最快的一条路。
